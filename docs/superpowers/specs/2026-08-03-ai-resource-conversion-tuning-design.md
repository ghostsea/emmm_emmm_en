# AI 资源转化与收益模型调优设计

## 目标

以当前 `master` 的 `0f70ef32` 为新基线，先建立真人与电脑可直接对照的资源流账本，再用固定种子定位真实断链，实施公司、外星人或具体资源循环的窄修复。第一验收目标是固定开发集与冻结随机验证集合并后的电脑席位均分提高至少 10 分；若较快达到，则继续冲击 20 分。最高分和高分段表现作为第二优先级保护，不用少数席位的回落换取虚高均值。

## 当前证据与问题边界

当前 `randomizer/game/ai/battle-analytics.js` 已能统计主要行动、快速步骤、资源锁、科技近失、低吞吐和公司表现，但没有统一拆分以下问题：

- 一局中有多少信用点、能量、手牌、数据和宣传来自开局、收入或非收入来源；
- 获得的资源有多少被继续投入主要行动，有多少留在终局或被低效转换；
- 蓝1、蓝2、公司被动和外星人补牌是否形成了完整的后续行动，而不是只提高静态库存；
- 真人在资源较少的情况下，如何通过数据板周转、补牌后打出、收入牌和外星人奖励维持更高行动密度。

参考日志已经提供可用证据。例如 `参考行动日志/宇宙战略374.md` 中的高分席位并非依靠反复取得蓝色科技，而是反复完成“补数据 -> 放置 -> 分析清空 -> 再补数据”，多次兑现蓝1信用点、蓝2能量及公司被动。当前模型需要衡量并预测这种闭环，不能给科技编号或当前资源余额固定溢价。

## 方案选择

### 方案一：直接调整现有权重

优点是改动快。缺点是无法区分资源获取、资源花费和真正产生行动的转化，容易让固定种子中的相关性扩散成全局规则。该方案不采用。

### 方案二：统一资源账本后做状态窄修复

先让真人 Markdown 日志和电脑自动对战都输出同口径资源指标，再从差距最大的公司、外星人或循环选择一个可验证断点。每次只改变一个行为假设，并用固定种子反事实和冻结随机种子守门。该方案为本轮采用方案。

### 方案三：增加多回合搜索深度

更深搜索有机会直接发现长链，但运行成本高，也会放大当前收益预测的不一致。在统一资源口径和一层行动收益仍有明显错误时不进入该方案；若窄修复无法达到 10 分目标，再单独设计搜索扩展。

## 实施拆分

本轮目标连续推进，但实现分成可以独立验证的子项目：

1. 资源流分析、真人日志解析、电脑日志接线和 `0f70ef32` 新基线；
2. 根据第一阶段证据选出的第一个具体行为断链；
3. 后续独立断链，直到固定集合达到均分门槛；
4. 行为冻结后的随机验证与最终汇总。

第一个实施计划只覆盖子项目 1，因为在资源证据产出前预写某个公司或外星人的行为代码会重新落入历史权重猜测。子项目 2 以后，每个行为修复都必须先写一份简短增量设计，明确触发状态、预测链、负面边界和成对种子，再生成不含猜测步骤的实施计划。该拆分不缩小最终 10/20 分目标；它只保证每个提交都有可审查的因果假设。

## 统一资源账本

### 资源与事件模型

新增纯分析模块，把真人和电脑日志先转换成同一类标准事件：

```js
{
  gameId,
  playerId,
  playerLabel,
  roundNumber,
  turnNumber,
  pace,             // setup | main | quick | pass | settlement
  sourceCategory,   // 见下方来源分类
  sourceDetail,
  resourceDeltas: { score, credits, energy, publicity, availableData, handSize },
  incomeDeltas: { credits, energy, publicity, availableData, handSize },
  cardIds,
  techIds,
  alienId,
  industryId,
  confidence,
}
```

`sourceCategory` 使用有限集合：

- `setup`：公司、顺位和初始牌带来的开局库存；
- `pass_income`：之后轮次 PASS 时实际领取的收入；
- `income_upgrade_immediate`：放入收入区时立即获得的一次资源；
- `tech_bonus_blue1`、`tech_bonus_blue2`、`tech_bonus_other`：科技附加位或科技能力的即时资源；
- `industry`：公司主动或被动奖励；
- `alien`：痕迹、面板、外星人卡和物种能力；
- `card`：打牌效果、任务或卡牌触发；
- `data_placement`、`analysis`：放数据、分析和数据板奖励；
- `planet_board`：发射、移动、环绕、登陆、扇区和星球奖励；
- `trade_conversion`：手牌、宣传等快速交易；
- `cost`：主要行动、快速行动和卡牌支付；
- `settlement`：终局或轮末结算；
- `unclassified`：有资源变化但来源尚不能可靠确定。

来源分类不得靠当前收益权重反推。文字日志以明确的“资源：”“收入：”、步骤来源和动作标题为准；电脑结构化行动日志以相邻快照的实际差值为准，步骤文本只负责来源归类。一个步骤同时出现叙述和汇总差值时只记一次。不能可靠分类的变化必须保留原文进入 `unclassified`，不能静默猜测。

### 两个输入适配器

1. 真人适配器读取 `参考行动日志/*.md`，解析终分表、路线摘要、行动标题和每个 `[setup]`、`[main]`、`[quick]` 步骤。它使用日志中已经生成的资源及收入差值，不改变原日志。
2. 电脑适配器读取自动对战结束时的可恢复行动日志。每个行动条目的恢复快照提供行动后玩家资源和收入；分析器与同玩家上一条快照对账，步骤文本提供来源。自动对战结果只保留聚合资源流及少量异常样本，不把完整恢复快照写入常规批跑 JSON。

两种适配器最终都调用同一个聚合器。这样真人与电脑的比较不会分别维护两套公式。

### 指标定义

每种资源分别输出绝对数量，涉及跨资源比较时使用 `docs/ai-design.md` 当前 L1 基础折算：信用点和能量每个 3，普通手牌约 3，数据每个 1.5，宣传每 1.5 个为 1.5。该折算只用于统计展示，不直接写回 AI 权重。

- `grossGain`：除结算分外，各来源正向资源变化之和；
- `incomeGain`：`pass_income` 与 `income_upgrade_immediate` 的正向资源变化；
- `nonIncomeGain`：游戏内 `grossGain - incomeGain - setupGain`；
- `spent`：所有负向资源变化的绝对值，按资源分别统计；
- `endingInventory`：终局剩余可支付资源；
- `utilizationRate = spent / (setupGain + grossGain)`，按资源计算，分母为 0 时返回 `null`；
- `nonIncomeShare = nonIncomeGain / (incomeGain + nonIncomeGain)`，不把开局资源放入分母；
- `weightedActionCost`：按 L1 折算后的主要行动与快速行动实际支出；
- `mainActionsPerWeightedCost = productiveMainActionCount / weightedActionCost`；
- `drawToPlayRate`：游戏内新增手牌中，随后作为打牌行动打出的比例；弃牌、移动支付和收入支付单列；
- `incomeCardConversionRate`：被放入收入区的牌数占所有用于支付、弃除或打出的新增牌比例；
- `dataTurnoverCount`：完成一次分析清空后又重新放入至少一个数据的次数；
- `fullDataCycleCount`：数据板达到分析要求、执行分析、随后再次达到分析要求的完整循环数；
- `blue1CreditGain`、`blue2EnergyGain`：蓝1/蓝2在整局实际发放的资源，而非持有科技的静态次数；
- `alienCardToPlayRate`：通过外星人获得的卡牌中，后来打出的比例；
- `sameRoundReinvestment`：非收入获得的信用点、能量或手牌在同轮后续被支付的数量与比例。

每项指标按玩家、轮次、公司和已揭示外星人分组，并提供高分四分位、低分四分位及全体均值。玩家日志的解析覆盖率以资源绝对变化量计，达到 98% 才可用于模型结论；所有剩余 `unclassified` 样本必须列出供人工检查。

## 基线与实验集合

### 固定开发集合

在任何行为修改前，以 `0f70ef32` 重新运行以下 8 局默认难度，保存每局逐席分数、行动统计、资源账本、`bugCount`、阻塞状态和步数：

- `codex-ai-current-default:1` 至 `codex-ai-current-default:5`；
- `codex-ai-resource-gap-alien-card-dev-20260731:fl`；
- `codex-ai-resource-gap-alien-card-dev-20260731:fm`；
- `codex-ai-resource-gap-alien-card-dev-20260731:fn`。

固定集合既是差距挖掘集，也是逐次反事实集合。一个行为候选必须使用相同种子、相同版本资源规则和相同浏览器脚本版本与基线成对运行。

### 冻结随机验证集

行为冻结后才首次运行以下 8 局默认难度，运行结果不得反向用于继续微调同一候选：

- `codex-ai-resource-flow-holdout-20260803:h01` 至 `codex-ai-resource-flow-holdout-20260803:h08`。

如果随机验证暴露明确规则 bug，可以先修 bug并另建下一组随机验证种子；不能把已查看的 h01-h08 改称未见留出。另以 `codex-ai-low-resource-baseline:2`、`:4`、`:5` 做 `weak_start` 安全回归，不把它们计入默认难度均分目标。

### 新基线产物

基线 JSON 放在 `tmp/`，不提交原始大文件。`docs/ai-design.md` 记录固定集合与随机验证集的聚合数字、关键逐席保护样本、资源差距结论和运行命令。用于比较的脚本、解析器和测试进入版本控制。

## 调优循环

### 第一阶段：只读差距分析

先比较真人高分四分位与电脑固定集合：

1. 每轮主要行动和快速步骤；
2. 收入、非收入和开局资源的构成；
3. 信用点、能量、手牌的使用率与同轮再投入；
4. 数据周转、分析次数及蓝1/蓝2实际发放；
5. 外星人补牌、精选和盲抽后的打出或弃除去向；
6. 按公司、外星人与轮次寻找最大差距。

结论必须指向具体状态链。例如“宇宙大战略在已有 6 个计算机、4 数据、可支付分析且扫描可再补 2 数据时，旧模型先扫描导致丢失一次清空/回填循环”。“真人蓝1更多”本身不是可实施结论。

### 第二阶段：一个假设一个修复

按证据优先级选择候选：

1. 能直接增加可支付主要行动或完整数据循环的资源断链；
2. 公司特定被动没有被后续行动现金化；
3. 外星人补牌、精选或收益牌存在明确可支付且未打出的近失；
4. 收益预测与实际执行选择不一致；
5. 最后才考虑全局基础权重。

每个候选先写失败测试，测试必须描述会改变行为的真实状态，而不是断言某个魔法常量。修复只处理该状态；固定 8 局立即成对验证。改善不稳定或高分保护失败时撤回行为改动，保留有价值的诊断与负面实验记录。

### 第三阶段：冻结和随机验证

固定集合达到门槛后冻结行为，运行 8 局随机验证和 3 局 `weak_start` 安全回归。随机集合允许逐局方差，但聚合均值、高分段和完整性门槛必须满足。若固定集合很快超过 10 分，则继续同一证据流程冲击 20 分，不能通过扩大宽泛加成直接追分。

## 验收门槛

### 第一优先级：均分

- 固定 8 局的 32 个席位均分相对新基线至少提高 10 分；
- 固定与随机验证共 16 局的 64 个席位合并均分相对各自同版本基线至少提高 10 分，才可宣称完成第一目标；
- 若第一目标在前两次已接受行为修复内达到，继续以相同门槛冲击合并均分提高 20 分。

### 第二优先级：高分保护

- 固定集合最高分不得低于基线；
- 固定集合与随机验证集合各自的最高四分位席位均分允许最多 2 分随机波动；
- 新基线中达到 300 分的保护席位，成对运行时不得下降超过 5 分；
- 若某个高分席回落但集合高分四分位和最高分都提高，必须在文档中解释具体行动重排，不能静默接受。

### 完整性和低尾守门

- `bugCount=0`、`blockedGames=0`，所有对局正常终局；
- 固定集合 P25 不得下降超过 3 分，最低席位不得下降超过 15 分；
- 随机验证出现单席明显回落时保留样本并判断是否为可复现断链，不能因均值通过而忽略；
- 真人日志资源解析覆盖率至少 98%，电脑资源快照对账差额为 0。

## 错误处理与提交同步

测试失败、自动对战阻塞、缓存版本错配或资源对账不平时，先停止调优：稳定复现、检查最近变更、定位数据在哪一层偏离，再补失败测试并修复根因。若问题是独立运行时 bug，单独提交修复后再重跑受影响的完整基线，不能沿用出错批次。

提交节奏如下：

1. 资源分析模块、真人解析器、测试和新基线文档作为第一个提交；
2. 每个通过固定集合的行为修正独立提交；
3. 随机验证与最终文档作为验证提交；
4. 修改 `randomizer/app/ai-controller.js` 后同步提升 `randomizer/index.html` 对应脚本查询版本，避免浏览器缓存污染 A/B；
5. 每个里程碑提交前运行语法检查、目标测试、全量 `randomizer/**/*.test.js` 和 `git diff --check`；提交后 fetch/rebase、push，并验证本地与 `origin/master` 的 SHA 一致、ahead/behind 为 `0 0`。

## 测试设计

- 纯聚合测试覆盖每种资源的正负变化、收入与非收入拆分、零分母、跨轮再投入和终局剩余；
- Markdown 解析测试使用最小内联片段，覆盖 setup、收入、蓝1/蓝2、公司、外星人、交易、同一行重复叙述与汇总差值；
- 结构化行动日志测试用两个连续恢复快照证明资源对账和来源分类；
- 数据循环测试覆盖一次分析后回填、两次完整分析循环和只有放置但未完成循环；
- 卡牌来源追踪测试区分普通盲抽、精选、外星人补牌，以及之后打出、收入、弃牌、移动支付和终局留手；
- 自动对战汇总测试证明单局及多局输出资源流，并且常规结果不携带完整恢复快照；
- 每个 AI 行为修正遵循红灯、绿灯、重构流程，并在固定种子批跑前完成全量单元回归。

## 文档边界

本设计只定义资源证据、实验流程和本轮调优门槛。实时收益公式、已接受的公司/外星人策略、基线数字和负面实验仍统一维护在 `docs/ai-design.md`。若资源分类揭示真实规则或状态模型错误，再同步对应机制文档；纯诊断字段不扩写 `AGENTS.md`。
