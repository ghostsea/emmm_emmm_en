# 数据循环统计口径修正

2026-09-06 的资源报告发现，同一个分析主行动后的快速移动、终局标记和奖励步骤可能沿用 `analysis` 来源分类。旧计数器把这些步骤当成新的分析，从而产生虚假的“分析—回填—再次分析”循环。该问题只影响报告；控制器的科技估值使用独立的主行动历史，没有读取这两个报告计数。

修正后的 `dataCycleCounting=distinct-main-entry-v2`：

- `analysisActionCount`：独立主行动条目中的分析次数，不能把收到别人分析触发的奖励算成自己的分析。
- `dataTurnoverCount`：分析后首次重新放置数据的次数，并非分析次数。
- `fullDataCycleCount`：一次分析之后发生过数据放置，再由下一次独立分析闭合的循环。
- 分轮 `analysisCount` 使用相同定义。正规化事件新增所属玩家的 `mainActionType`，即使方舟揭示奖励替换了可见支付文本，仍能保留原分析边界。

[重算结果](2026-09-06-data-cycle-count-correction.json) 保留旧值和新值。真人15席可见完整循环均值从4.7333修正为4.5333；最初8组基线32席从3.625修正为3.09375。不同日志、公司和版本的样本不能当作因果对照。

旧12组随机结果有6个“版本×席位”的第一次分析原始文本在揭示结算后缺失，旧资源事件也未保留所属主行动类型，因此其重算计数比AI决策日志少1。这些条目逐一保留在 `mismatches` 中；旧循环统计是可恢复事件的计数，不能宣称完整。没有通过放宽规则把其他玩家收到的奖励推定成分析。新版事件使用明确归属的主行动类型解决后续报告的此类缺失。

旧实验JSON中的循环字段不应继续直接比较，需使用本重算口径和上述缺失限制；它们的终分、资源余额、收入/非收入资源量、消耗量和确认主行动总数不因本计数修正而改变。寰宇蓝2第3组的实际分析主行动为2→3，重算完整循环为1→2；之前将旧回填字段1→3说成分析次数的表述已撤回。
